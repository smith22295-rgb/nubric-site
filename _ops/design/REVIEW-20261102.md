# Design review — 2 November 2026

## Decision

Two real-content homepage concepts were compared at desktop and mobile sizes. The selected direction uses an open, light masthead with an upright project presentation. The alternate dark, oversized masthead delayed the work too far down the mobile page. References informed hierarchy and the customer journey; no third-party design or assets were copied.

## Changes

- Replaced the tilted browser illustration with larger real project imagery, contextual descriptions and accessible project tabs.
- Removed the repeated homepage project grid. The album-style portfolio remains the full collection.
- Used direct service names and a consistent free-consultation navigation action.
- Shortened selected introductions and aligned typography, spacing, color roles, service cards, pricing and footer navigation across 27 studio pages.
- Consolidated shared CSS rules rather than adding another page-wide patch stylesheet. Kept fingerprinted assets for safe caching.
- Added a project brand brief and a reusable design skill. The skill's source is backed up in this directory; each client keeps their own brand identity.

## Verification

- Reviewed desktop, tablet and phone layouts, including narrow 320px viewports. Fixed a mobile shop-grid overflow caused by conflicting media-query order.
- Inspected desktop/mobile screenshots for hierarchy, image framing and readable controls; corrected a missing heading space found during visual review.
- Exercised homepage project tabs, mobile navigation, portfolio controls and drag, outdoor customization and inquiry preview, service-estimate totals, and the guided assistant request flow.
- Verified demo-to-contact links preselect the correct service and request context. Required fields and the existing form action remain intact. No test inquiry was sent.
- Static checks verify internal resources/anchors, heading IDs, package prices, preservation of scripts, metadata, forms and legal/commercial content. Existing security and gallery-gesture checks are part of the release verification.
- All executable JavaScript is unchanged. Existing consent-based analytics, app support and legal routes remain in place.

## Limits and next evidence

These are implementation and visual checks, not customer research or evidence of increased conversion. Mail delivery was not re-tested, and physical iOS/Android devices were not used. The next useful research is to observe a few prospective customers independently find a suitable package, explore relevant work and start a consultation. Record misunderstandings before making more design changes.

Future substantial design work follows `BRAND.md` and the `nubric-web-design` skill. Small corrections should remain small.
